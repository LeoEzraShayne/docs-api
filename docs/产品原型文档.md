# XX要件定義 — V1 补充规格（上线必备 / Cursor-Codex可执行）

> 目标：把 V1 从“能跑”补齐到“能上线收钱、少翻车”。

## 0. 已确认决策（锁定）

- Frontend：Next.js(App Router) + Tailwind
- Backend：NestJS
- 登录：Google 第三方登录 + 邮箱验证码登录
- 邮件服务：Resend（发送验证码）
- 支付：Stripe（JPY）
- 配置/域名/安全：Cloudflare（DNS/WAF/Rate Limit等）

- 未付费：仅体验固定示例结果；不免费处理用户自己的材料
- 输出：五类文档的 Excel xlsx（要件定義、基本設計、詳細設計、単体テスト仕様、結合テスト仕様）
- 文件存储：非必须（保存 input + extractedJson + versions；xlsx 可随时重建）

## 1) 登录方案（最省事 + 可控）

### 1.1 Google 登录（推荐实现）

前端 Next.js 走 Google OAuth，拿到 `id_token` 后发给后端换你自己的 JWT。

- POST /auth/google
  - req: { idToken: string }
  - backend: 校验 idToken（Google 公钥 / tokeninfo），拿到 email/sub
  - upsert user
  - resp: { token, user:{id,email} }

### 1.2 邮箱验证码登录（Resend）

- POST /auth/start { email }
  - 生成 6 位 code，TTL=10分钟
  - 发送邮件（Resend）
  - 限频：同邮箱 60 秒内只能发一次；同IP 10分钟最多 X 次
- POST /auth/verify { email, code }
  - 校验成功 → 返回 JWT

> 注意：验证码存储建议用 DB 表或 Redis（V1可DB，后面再Redis）。

## 2) 付费权益与生成次数（V1）

### 2.1 计费单位

- 一份文档指：用户选择五类文档中的一种，针对一个项目生成一份最终成果。
- Single：`¥980（税込）/ 1文書`，购买后 7 天内最多完整生成 3 次。
- Business Pack：`¥66,640（税込）/ 78文書`，可在五类文档间自由使用；未启用额度 12 个月有效。
- Business Pack 中每启动一份文档，同样获得该文档 7 天内最多 3 次完整生成。
- V1 不提供月费订阅，不提供无限生成。

### 2.2 生成与下载规则

- 完整生成成功并保存版本后，消耗该文档 1 次生成机会。
- 用户修改输入后重新生成，也消耗 1 次生成机会。
- 系统失败、模型失败、Excel worker 失败不消耗次数。
- 同一已生成版本重复下载免费，不再次消耗生成次数。
- 第 3 次完整生成完成后，如仍需修改，需重新购买一份文档权益。

## 4) Stripe 支付（必须补齐）

### 4.1 产品/价格

- Single Document：`¥980（税込）`，1 文档、7 天内最多完整生成 3 次
- Business Pack：`¥66,640（税込）`，78 文档额度、未启用额度 12 个月有效
- 页面视觉重点放在 Single；Business Pack 用作批量入口与价格对比

### 4.2 成本与利润校验（保守估算）

- 假设 DeepSeek-V4-Pro 单次完整生成使用 25,000 input tokens + 20,000 output tokens，且输入缓存未命中。
- 按官方当前单价估算，单次模型成本约 `¥4.58`，一份文档用满 3 次约 `¥13.74`。
- 计入 10% 消费税与 Stripe 3.6% 手续费后，Single 用满 3 次的直接利润约 `¥841.89`，直接利润率约 `94.5%`。
- Business Pack 共最多 234 次完整生成；相同假设下直接利润约 `¥57,111.82`，直接利润率约 `94.3%`。
- 上线后必须记录实际 token usage、缓存命中、生成次数、退款和支持成本，再调整次数或价格。

### 4.3 Webhook 必处理事件

- checkout.session.completed（Single / Business Pack 支付成功后发放权益）
- charge.refunded / refund.updated（出现退款例外时同步权益状态）

### 4.4 退款策略（页面文案要写）

- 数字内容性质上，完整生成开始后原则不可退款。
- 重复扣款、支付后系统无法提供生成服务、或法律要求的情形除外。
- 系统失败不扣生成次数；若无法恢复服务，按例外退款处理。

## Defaults & Policies（V1 固定规则，避免实现发散）

### A. 認証・セキュリティ

- JWT 保存方式：**httpOnly Cookie**（默认，不用 localStorage）
- 认证策略：所有 /app、/account、/projects、/generate、/download 需要登录
- RequestId：后端为每个请求生成/透传 requestId，前端错误提示展示 requestId
- Rate Limit（建议写到Cloudflare + 后端双层）：
  - /auth/start：同IP 1分钟<=5次；同email 60秒<=1次
  - /auth/verify：同IP 10分钟<=20次（防爆破）
  - /projects/*/generate：同IP 1分钟<=3次；必须校验已付款文档权益
  - /billing/checkout：同IP 1分钟<=3次

### B. 免费体验限制

- 未购买用户不提交自己的资料进行 AI 生成。
- Sample Demo 只返回服务器保存的固定示例结果，不调用 DeepSeek。
- Sample Demo 防白嫖（强制）：
  - 各 Tab 只显示前 5 行
  - 隐藏高价值列（FUNCTIONS：受入条件/例外；NFR：目標/エビデンス；RISKS：対応案/判断点等）
  - UI 显示 “Sample / Preview” 标识

### C. 生成 / 模型策略

- 用户自有材料生成：必须绑定已购买的 Single 文档权益或 Business Pack 文档枠。
- 扣次数规则：完整内容生成成功并保存 version 后扣 1 次；Excel 下载不扣次数。
- 同一文档权益仅允许选择一种文档类型，最多生成 3 个完整版本。
- 模型：V1 统一使用 DeepSeek-V4-Pro；保存 input/output/cache-hit token usage 供成本复盘。
- 缓存：将固定提示词和项目基础材料置于请求前部以争取缓存命中，但利润测算按未命中计算。
- 生成冷却：同项目 30 秒内不允许重复 generate（防连点）
- 输入长度上限：minutes_text <= 20,000 字符（超出提示拆分）

### D. 有效期

- Single：购买日起 7 天有效，到期后未使用的生成次数作废。
- Business Pack：未启动的文档枠购买日起 12 个月有效；启动某份文档后，该份文档的 3 次生成窗口为 7 天。
- V1 无订阅周期、无月度额度重置。

### E. 税/退款/法务

- 页面价格显示：**税込**（例：¥980（税込））
- 退款：完整生成开始后原则不可退款；重复扣款、系统无法提供服务或依法必须退款除外
- 必须提供：/terms /privacy /contact

### F. 数据与隐私

- 保存内容：表单输入、会议纪要文本、抽取结构化JSON、版本历史
- 文件存储：xlsx 文件可不持久化（可随时用 extractedJson 重建）
- 数据保留期限：**180 天无操作自动清理**（V1默认）
- 用户操作：支持“删除项目”（默认：**硬删除**，简单且符合隐私）
- 不提供：结构化JSON导出给用户（防被当免费API）

### G. 技术默认

- ORM：**Prisma**
- 验证码存储：V1用 DB（后续可上 Redis）
- Excel 生成：**Python excel-worker（FastAPI）**，NestJS 调用并将 xlsx 流式返回

## Demo & Alerting（MVP+，高性价比）

### Demo（ログイン不要の体験）

目的：Landing→体験→購入の導線を短くしてCVRを上げ、未購入ユーザーの資料を無料処理しない。

仕様：

- Landing に「デモで試す」ボタンを追加

- デモは preview のみ（xlsxダウンロード不可）
- デモ入力と結果は固定のサンプル（機密なし、汎用のEC/申請など）
- 結果は事前生成して保持し、デモアクセス時に DeepSeek を呼び出さない
- デモ結果は preview 表示ルールを適用（各タブ先頭5行・高価値列非表示・Preview表示）

API：

- POST /demo/preview
  - req: { }（固定サンプル結果を返却）
  - resp: previewと同じ構造（tabs + paywall）
- デモ表示後、CTA「¥980で作る」→ /login or /app/new

制限：

- デモはIP単位で rate limit（例：1分1回、1日3回）

### Alerting（障害検知・即時通知）

目的：ユーザーからの苦情前に異常を検知。

最低限の通知トリガー：

1) Excel生成失敗率が高い（例：5分間で失敗率>20% かつ 件数>=10）
2) DeepSeek 呼び出し失敗が連続（例：連続5回）
3) Stripe webhook 受信エラー（検証失敗/例外）
4) excel-worker health check が失敗（連続3回）

通知先（MVP）：

- support/admin のメールへ送信（ResendでOK）
- 送信内容：timestamp, env, requestId例, error要約, 発生件数, 直近ログ参照キー
