# Docs AI 产品原型文档（当前实现版）

> 更新时间：2026-06-02  
> 目标：记录当前已经落地的产品、页面、计费权益和上线约束，作为后续维护与回归验证依据。

## 0. 产品定位

Docs AI 是面向业务资料整理的 AI 文书生成工具。用户登录后创建案件，录入项目资料或选择上游文书，系统生成 Excel 形式的交付文档。

当前支持五类文书：

| 文书类型 | 日文显示名 | 输出 |
| --- | --- | --- |
| REQUIREMENTS | 要件定義書 | xlsx |
| BASIC_DESIGN | 基本設計書 | xlsx |
| DETAILED_DESIGN | 詳細設計書 | xlsx |
| UNIT_TEST | 単体テスト仕様書 | xlsx |
| INTEGRATION_TEST | 結合テスト仕様書 | xlsx |

## 1. 技术与环境

- Frontend：Next.js App Router + Tailwind。
- Backend：NestJS + Prisma。
- 登录：Google 登录 + 邮箱验证码登录。
- 邮件服务：Resend。
- 支付：Stripe，JPY。
- AI：DeepSeek 系列模型配置在后端环境变量中。
- Excel：后端调用 Excel worker 生成 xlsx。
- 前端线上：Cloudflare 自动部署。
- 后端线上：GitHub 推送后通过 GitHub Actions 部署到腾讯云。
- 本地环境使用 Stripe 测试环境，线上环境必须使用 Stripe 正式环境。

## 2. 登录

### 2.1 Google 登录

- 前端通过 Google Identity Services 获取 `idToken`。
- 后端 `POST /auth/google` 校验 token，成功后写入 httpOnly Cookie。
- Google 登录失败时，前端只显示日语业务文案，不显示 `Request ID`。
- 网络失败文案：`サーバーに接続できません。時間をおいて再度お試しください。`

### 2.2 邮箱验证码登录

- `POST /auth/start` 发送 6 位验证码。
- `POST /auth/verify` 校验验证码并登录。
- 验证码 10 分钟有效。
- 同邮箱 60 秒内限制重复发送。
- 所有登录相关错误均显示日语文案。

## 3. 计费产品

### 3.1 Docs Single

价格：`¥980（税込）`

规则：

- 每次购买只绑定一种文书类型。
- 购买后在账户页立即显示购买履历。
- 购买后即使还未进入文书页面激活 grant，账户页也显示 Docs Single 信息。
- 购买后 7 天内有效。
- 每份 Docs Single 可生成 3 次。
- 付与内容显示：`3回生成`。
- 对象文书显示具体文书名，例如 `要件定義書`，不显示购买数量。

### 3.2 Business Pack

价格：`¥66,640（税込）`

规则：

- 一次购买获得 78 次共享生成额度。
- 五类文书共享同一个 Business Pack 余额。
- Business Pack 未使用余额有效期为购买后 12 个月。
- 任意一种文书生成成功后，Business Pack 余额整体减 1。
- 文書別利用状況中，五类文书展示同一个 Business Pack 剩余余额。
- 付与内容显示：`78回生成`。
- 对象文书显示：`全文書`。

### 3.3 Docs Single 与 Business Pack 并存

用户可同时持有 Business Pack 和 Docs Single。

生成扣减规则：

- 如果当前文书存在 Docs Single 的可用次数，优先扣 Docs Single。
- 如果没有可用 Docs Single，则扣 Business Pack。
- 文书页面显示的 `残り生成回数` 为：Business Pack 剩余次数 + 当前文书 Docs Single 剩余次数。

示例：

- Business Pack 剩余 77 次，未购买 Docs Single：五类文书都显示 77。
- 此时购买要件定義書 Docs Single：要件定義書显示 80，其他四类文书显示 77。
- 生成要件定義書一次后，如果优先扣 Docs Single，则要件定義書显示 79，其他四类仍显示 77。

## 4. 权益激活与生成规则

- 用户自有资料生成必须有可用权益。
- 生成成功并保存版本后才扣次数。
- 模型失败、Excel worker 失败、系统异常不扣次数。
- 同一版本重复下载不扣次数。
- 文书生成页在有权益时显示：
  - `文書生成`
  - 文书名
  - `案件: {案件名}`
  - `残り生成回数: {次数}`
- grant 不存在且没有可用权益时，不显示残り生成回数。
- 同一文书 30 秒内禁止重复生成，文案显示：`30秒待ってから再実行してください。`
- 错误提示中不展示 `Request ID`，但后端仍保留 request id 供日志排查。

## 5. 案件与 Workspace

### 5.1 新規案件

- 免费用户最多可创建 3 个案件。
- 案件标题为空时使用 `無題の案件`。
- 输入文本上限为 20,000 字符。
- 新规案件中选择 Excel 生成后，生成成功会创建案件并进入对应预览/文书页面。
- 生成后的案件必须在左侧 PROJECTS 菜单和右侧案件一覧中同时出现。

### 5.2 案件一覧页面

右侧案件一覧采用短卡片分页布局：

- 默认每页 12 件。
- 可选择 12 / 24 / 48 件。
- 案件卡片每行最多 3 个。
- 页面顶部显示：
  - 合计
  - 生成済み
  - 最終更新
- 每张卡片显示：
  - 案件名
  - 更新时间
  - 状态
  - `開く`

### 5.3 左侧 PROJECTS 菜单

左侧 PROJECTS 菜单与右侧案件一覧保持同一分页数据：

- 右侧显示第几页，左侧也显示同一页案件。
- 菜单底部有 `前へ / 次へ`。
- 展开案件后显示五类文书。
- 已生成版本显示为 `v1`、`v2` 等。
- 当用户有 100 个案件时，不在菜单一次性显示 100 个，而是通过分页浏览。

## 6. 文书生成页面

### 6.1 共通结构

每类文书页面包含：

- 标题卡片：文书名、案件名、残り生成回数。
- 输入来源选择。
- 标准版 / カスタム 等生成模式。
- 生成按钮。
- `1文書を購入` 按钮。
- 版本列表，可重复下载生成过的 xlsx。

生成按钮：

- 有权益时可直接生成。
- 无权益时提示购买。

购买按钮：

- 跳转 Stripe Checkout。
- 支付成功后回到当前文书页面。
- 返回后页面显示最新残り生成回数。

### 6.2 上游文书与直接入力

五类文书都支持按当前代码配置选择来源：

- 要件定義書：使用案件信息生成。
- 基本設計書：可使用要件定義書或直接入力。
- 詳細設計書：可使用基本設計書或直接入力。
- 単体テスト仕様書：可使用詳細設計書或直接入力。
- 結合テスト仕様書：可使用詳細設計書或直接入力。

直接入力生成成功后，也必须进入账户页的 `文書別利用状況`。

## 7. Account / 利用状況页面

### 7.1 顶部汇总

账户页展示当前用户邮箱与权益概览。

Business Pack 汇总：

- `利用形態`: Business Pack。
- `利用状況`: `{残り} 残り / 生成済み {生成済み数}`。
- `有効期限`: Business Pack 最晚有效期。
- 卡片布局为 3 等分，避免上下两行数量不一致。

Docs Single 汇总：

- `利用形態`: Docs Single。
- `購入済み文書数`: 已购买 Docs Single 数。
- `次に失効する文書`: 显示最早失效的 Docs Single 文书，例如 `要件定義書：2026/6/9`。
- 如果只有 Business Pack，没有 Docs Single，则不显示 Docs Single 区块。
- 初始化没有购买数据时，不显示 `利用を続けるには追加購入してください。` 这类提示。

数字显示规则：

- 所有数量使用日文数字格式。
- 超过 999,999 时显示 `999,999+`，避免 UI 被超长数字撑破。

### 7.2 文書別利用状況

表格列：

- 案件
- 文書
- 生成回数
- 残り生成回数
- 有効期限
- 状態

规则：

- 有生成版本的文书必须显示。
- 有 grant 的文书必须显示。
- 直接入力生成的文书也必须显示。
- `生成回数` 使用当前文书版本数。
- `残り生成回数` 使用统一权益规则：
  - Business Pack 剩余共享次数 + 当前文书 Docs Single 剩余次数。
  - 纯 Docs Single 显示该文书 grant 剩余次数。
- `有効期限`：
  - 有 Business Pack 时显示 Business Pack 有效期。
  - 否则显示当前文书 grant 有效期。
- `状態`：
  - 有可用 Business Pack 或当前文书 grant 剩余次数大于 0，显示 `利用中`。
  - 否则显示 `利用不可`。
- 分页与購入履歴一致，支持 10 / 30 / 50 件。

### 7.3 購入履歴

表格列：

- 購入日時
- 商品名
- 対象文書
- 金額
- 支払い状態
- 付与内容

规则：

- Stripe 支付成功后，进入账户页必须立即展示购买履历。
- 购买履历与是否已经生成文书无关。
- Docs Single：
  - 商品名：Docs Single。
  - 対象文書：具体文书名。
  - 付与内容：`3回生成`。
- Business Pack：
  - 商品名：Business Pack。
  - 対象文書：`全文書`。
  - 付与内容：`78回生成`。
- 分页支持 10 / 30 / 50 件。

## 8. Demo 页面

目标：让用户看到产物质量，但不免费处理用户自己的资料。

当前实现：

- 路径：`/demo`。
- CTA 文案：`自分の資料で作成する`。
- 已登录用户点击 CTA 进入 `/app/new`。
- 未登录用户点击 CTA 进入 `/login?next=/app/new`。
- 下方说明：`正式生成・Excel出力は 1文書 ¥980（税込）`。
- Demo 使用固定样例输入，不接收用户自己的资料。
- 返回结果只展示被遮蔽后的 preview。
- xlsx 下载不可。
- 前端使用 sessionStorage 缓存 demo preview，避免同一浏览器反复请求。

限流：

- 同 IP 1 分钟内只能请求 1 次。
- 同 IP 东京日期内最多请求 3 次。
- 触发 1 分钟限流时显示：
  - `デモプレビューの表示回数が短時間に集中しています。1分後に再度お試しください。`
- 触发日限流时显示：
  - `本日のデモ利用上限に達しました。明日以降に再度お試しください。`
- 初始加载时如果没有触发限流，不显示失败提示。

## 9. Pricing 页面

页面展示两种购买入口：

- Docs Single：`¥980（税込）`
- Business Pack：`¥66,640（税込）`

购买失败、网络失败、Stripe session 不属于当前用户等错误，只显示日语业务文案，不拼接 request id。

## 10. 错误提示规范

前端 UI 不展示 `Request ID`。

示例：

- 网络失败：`サーバーに接続できません。時間をおいて再度お試しください。`
- 30 秒生成冷却：`30秒待ってから再実行してください。`
- 无购买枠：`文書生成に利用できる購入枠がありません。`
- 无剩余次数：`この文書の残り生成回数がありません。`
- Google 登录失败：`Googleログインの認証に失敗しました。`

后端仍保留：

- request id middleware。
- 响应 header 中的 request id。
- 日志链路中的 request id。

## 11. 数据与保留

保存内容：

- 用户。
- 登录验证码。
- 案件。
- 文书。
- 文书版本。
- 生成输入。
- 抽取后的结构化 JSON。
- 支付记录。
- 文书权益 grant。
- 文书额度 credit。
- demo preview 使用记录。

清理规则：

- 180 天无操作的案件每天自动清理。
- 删除案件为硬删除。

## 12. API 概览

Auth:

- `POST /auth/google`
- `POST /auth/start`
- `POST /auth/verify`
- `GET /auth/me`
- `POST /auth/logout`

Billing:

- `GET /billing/me`
- `GET /billing/account-usage`
- `GET /billing/purchases?page=&pageSize=`
- `POST /billing/checkout/single-document`
- `POST /billing/checkout/business-pack`
- `POST /billing/checkout/confirm`

Projects:

- `GET /projects`
- `GET /projects?page=&pageSize=`
- `POST /projects`
- `GET /projects/:id`
- `PUT /projects/:id`
- `DELETE /projects/:id`

Documents:

- `GET /projects/:id/documents`
- `GET /projects/:id/documents/tree`
- `GET /projects/:id/documents/:type`
- `POST /projects/:id/documents/:type/generate`
- `GET /projects/:id/documents/:type/versions/:versionNo/download`

Demo:

- `POST /demo/preview`
