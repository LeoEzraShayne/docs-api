# Prompt F（给 Codex：生成 単体テスト仕様書 页面）

You are building the "Unit Test Specification" page for the SaaS product 「XX要件定義」.

This page belongs to:

/app/projects/[projectId]/documents/unit-test

Implement ONLY the Unit Test Specification page.

Do NOT redesign the platform.

Use the same UI style, layout, authentication, billing, progress bar, download mechanism, version management, and generation workflow already implemented in Prompt C, Prompt D, and Prompt E.

---

# Business Concept

Document Type:

UNIT_TEST

The generated result is:

単体テスト仕様書.xlsx

The purpose of this page is to generate practical unit test specifications that testers can execute directly.

Do NOT generate unnecessary summary sheets.

Do NOT generate a separate test result sheet.

Execution-related columns such as 実施者, 実施日, 備考 should be included directly in each test sheet and left blank for users to fill in after testing.

# Standard Version

Generate 3 Sheets.

---

Sheet1

画面テスト

Columns:

| No | 画面ID | テスト項目 | 前提条件 | テスト手順 | 期待結果 | 実施者 | 実施日 | 備考 |

Rules:

- Generate test cases based on screen items, screen processing, input checks, and selected test viewpoints.
- 実施者, 実施日, 備考 must be generated as empty columns.
- Do NOT fill execution result values.

---

Sheet2

APIテスト

Columns:

| No | API ID | テスト項目 | 前提条件 | テスト手順 | 期待結果 | 実施者 | 実施日 | 備考 |

Rules:

- Generate test cases based on API definitions, request/response parameters, authentication, errors, and selected test viewpoints.
- 実施者, 実施日, 備考 must be generated as empty columns.
- Do NOT fill execution result values.

---

Sheet3

DBテスト

Columns:

| No | テーブル名 | テスト項目 | 前提条件 | テスト手順 | 期待結果 | 実施者 | 実施日 | 備考 |

Rules:

- Generate test cases based on table definitions, table items, data creation, update, delete, and history requirements.
- 実施者, 実施日, 備考 must be generated as empty columns.
- Do NOT fill execution result values.

# Important Rules

The Unit Test Specification must be based on detailed implementation-level information.

If Source = 詳細設計書:

Use selected Detailed Design Document as the main source.

If Source = 直接入力:

Use manually entered screen list, API list, table list, selected test viewpoints, and additional notes.

Do NOT ask users to enter requirement-level fields such as:

- 解決したい課題
- 実現したいこと
- 主な機能

Unit test generation should be fast and checkbox-driven.
