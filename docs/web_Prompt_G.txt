# Business Concept

Document Type:

INTEGRATION_TEST

The generated result is:

結合テスト仕様書.xlsx

The purpose of this page is to generate business scenario test cases.

Integration testing means testing a chain of related functions as one business scenario.

Example:

ログインシナリオ

関連機能:

- 認証コード送信
- ログイン

テスト手順:

1. 認証コードを送信する
2. ユーザーID、パスワード、認証コードを入力する
3. ログインする

期待結果:

ホーム画面に遷移する

---

# Important Concept

Unit Test:

Tests a single screen, API, or database operation.

Integration Test:

Tests multiple related functions as one business flow or business scenario.

Do NOT generate separate sheets for external system tests.

External system calls should be included inside business scenario test steps when relevant.

Example:

決済シナリオ should include:

- 注文作成
- 決済実行
- 決済結果確認
- 注文ステータス更新

# Standard Version

Generate 1 Sheet.

---

Sheet1

業務シナリオテスト

Columns:

| No | シナリオ名 | 関連機能 | 前提条件 | テスト手順 | 期待結果 | 実施者 | 実施日 | 備考 |

Rules:

- Generate business scenario test cases.
- Each scenario must combine multiple related functions.
- テスト手順 must include multiple ordered steps.
- 関連機能 should list the functions used in the scenario.
- 実施者, 実施日, 備考 must be generated as empty columns.
- Do NOT fill execution result values.
- Do NOT create separate external integration sheets.
- If external system integration exists, include it as part of the business scenario steps.

Examples:

Scenario:

ユーザー登録シナリオ

Related functions:

認証コード送信、ユーザー情報入力、ユーザー登録、登録完了

Test steps:

1. 認証コードを送信する
2. 認証コードを入力する
3. ユーザー情報を入力する
4. 登録ボタンを押下する

Expected result:

ユーザー登録が完了し、完了メッセージが表示される

---

Scenario:

注文・決済シナリオ

Related functions:

商品検索、カート追加、注文作成、決済実行、注文完了

Test steps:

1. 商品を検索する
2. 商品をカートに追加する
3. 注文内容を確認する
4. 決済を実行する
5. 注文完了画面を確認する

Expected result:

注文が完了し、注文ステータスが更新される
