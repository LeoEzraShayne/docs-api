# Current Problem

The current Workspace sidebar only shows:

WORKSPACE
- 案件一覧
- 新規案件
- アカウント

But the product specification requires a project-based document tree.

The sidebar must support:

1. Creating a new project quickly.
2. Viewing the project list.
3. Opening each project.
4. Opening five document generation pages under each project.
5. Showing document versions under each document type.
6. Refreshing the version tree after a new document version is generated.

# Sidebar Behavior

## 1. Workspace menu

The top workspace menu must always show:

- 新規案件
- 案件一覧
- アカウント

Order must be exactly:

1. 新規案件
2. 案件一覧
3. アカウント

Routes:

- 新規案件:
  /app/new

- 案件一覧:
  /app

- アカウント:
  /account

Highlight the active item based on current route.

---

## 2. Project list

Show all user projects under a separate PROJECTS section.

Each project must be collapsible / expandable.

If there are many projects:
- The project list area should be scrollable.
- Keep the WORKSPACE menu visible near the top.
- Do not let the sidebar become unusable.

Each project row should display:
- Project name
- Expand / collapse indicator

Clicking the project name should open:

/app/projects/[projectId]

---

## 3. Document type nodes

When a project is expanded, show the five document types:

1. 要件定義書
2. 基本設計書
3. 詳細設計書
4. 単体テスト仕様書
5. 結合テスト仕様書

Each document type must always be visible even if it has no versions yet.

Routes:

- 要件定義書:
  /app/projects/[projectId]/documents/requirements

- 基本設計書:
  /app/projects/[projectId]/documents/basic-design

- 詳細設計書:
  /app/projects/[projectId]/documents/detailed-design

- 単体テスト仕様書:
  /app/projects/[projectId]/documents/unit-test

- 結合テスト仕様書:
  /app/projects/[projectId]/documents/integration-test

Clicking a document type opens the corresponding generation page.

If the document type has no versions:
- Do not show version nodes.
- Clicking the document type still opens the generation page.

---

## 4. Version nodes

Under each document type, show existing versions:

- v1
- v2
- v3

Version click behavior:

Clicking a version should open the corresponding document page with the selected version.

Use the query parameter:

?version=v1

Examples:

/app/projects/[projectId]/documents/requirements?version=v1

/app/projects/[projectId]/documents/basic-design?version=v2

/app/projects/[projectId]/documents/detailed-design?version=v1

/app/projects/[projectId]/documents/unit-test?version=v3

/app/projects/[projectId]/documents/integration-test?version=v1

Highlight the active version based on current route and query parameter.

2. The new version must appear immediately under the correct:
   - project
   - document type
3. Do not require a full page reload.
4. Do not require the user to manually refresh the browser.

If the existing implementation has an event, callback, or mutation system, use it.
If not, implement a simple refresh mechanism:

- After successful generation, call the sidebar refresh function.
- Or invalidate/refetch the project documents query.
